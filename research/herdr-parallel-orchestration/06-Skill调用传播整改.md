# 2026-08-31：Skill 调用传播整改

## 1. 问题输入与事实边界

用户报告了一项已经发现的失效场景：主智能体向普通智能体派发责任时，把 `$herdr-parallel-orchestration` 写入提示词，接收者因此启用本 Skill 并继续派发其他智能体，存在递归或持续派发的风险。

本阶段以用户报告的失效场景、本轮对话中的规则辨析和当前 Skill 源码为事实源。用户进一步澄清：问题不是 Skill 元数据或普通智能体自行发现 Skill，而是主智能体把显式调用写进了派发提示。本阶段没有通过独立的真实 Codex 或 Herdr session 复现整改后的行为。

## 2. 失效原因

Skill 调用属于当前主智能体的编排约束，不是结果责任链的一部分。主智能体把调用写入派发提示后，调用会随责任链进入另一个智能体的上下文，使接收者可能把自己也置于编排角色并继续扩展工作面。

这个问题只能在派发方控制。接收者无法可靠判断自己是否属于“下游”，也无法从提示内容可靠区分用户输入和上级智能体输入，因此不能把防护建立在接收者识别来源或角色的能力上。

## 3. 护栏设计如何收敛

本轮先后排除了以下不合适的表达：

| 表达方向 | 问题 | 收敛结果 |
|---|---|---|
| 修改 Skill 元数据，限制自动触发 | 与实际失效原因不符；普通智能体不是通过自动发现触发 | 保持元数据不变，只约束派发行为 |
| 在 Skill 正文写“只有用户可以显式调用” | 这是给使用者看的调用说明，不是 Skill 生效后对智能体的行为要求 | 正文只写智能体能够执行的约束 |
| 要求接收者判断自己是下游或识别上级提示 | 接收者没有可靠的角色和消息来源事实 | 把控制点放在生成派发提示的主智能体 |
| 只约束 `herdr agent prompt` | 把一般性的责任派发护栏错误收窄到单一命令 | 使用 Herdr Agent、普通智能体和内置子代理这一语义化适用范围 |
| 规定提示词“只说明”若干字段 | 形成新的内容白名单，会排除退出条件、权威来源、已关闭决策和可自主继续的相邻工作 | 不限制原有责任链内容，只禁止传播 Skill 调用和继续启用要求 |
| 说明“其他提示内容照旧” | 没有增加有效约束，只重复未改变的事实 | 删除冗余说明 |

失效护栏沿用同节既有规则的结构：标题先指出需要阻止的失效结果，正文再限定适用场景、禁止行为和编排边界。具体工具参数只用于工具级失效；一般派发规则使用语义化场景，不绑定单一命令。

## 4. 形成的规则

本阶段在 `skills/herdr-parallel-orchestration/SKILL.md` 的“已验证的失效护栏”中增加：

> **Skill 调用不得沿派发链传播**：向 Herdr Agent、普通智能体或内置子代理派发责任时，提示词中不得包含 `$herdr-parallel-orchestration`，也不得要求接收者启用或继续使用本 Skill。本 Skill 只约束当前主智能体的编排，不属于其他智能体的结果责任链。

这条规则只切断 Skill 调用的传播，不改变结果责任链原有的结果、退出条件、所有权、权威来源、授权边界和自主推进范围。

## 5. 阶段结论

- 编排 Skill 的调用不能成为派发提示的一部分；责任链传递工作责任，不传递主智能体的编排身份。
- 失效护栏必须约束掌握必要事实且能够控制行为的一方，不能要求接收者推断不可见的消息来源或层级角色。
- 新护栏应只改变目标失效对应的行为，不能通过内容白名单、额外术语或单一工具绑定意外收窄原有派发能力。
- Skill 正文保存智能体可执行的行为要求；面向使用者的调用资格说明不混入失效护栏。
