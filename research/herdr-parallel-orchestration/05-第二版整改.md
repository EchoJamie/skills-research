# 2026-08-30：第二版整改

## 1. 整改输入

第二版以 [04-首次运行评估.md](04-首次运行评估.md) 的阶段结论为主要依据，并补回第一版形成前已经出现、但没有进入 Skill 的非阻塞派发建议：

- 并行责任使用 `herdr agent prompt` 时默认不加 `--wait`，提交后主智能体继续自己的责任。

首次运行中反复出现的 Skill 遗忘问题则形成另一项整改输入：用户显式调用后持续遵循该 Skill，只有用户明确要求不再使用时退出。

## 2. 改良内容

| 改良 | 形成的规则 |
|---|---|
| 工作守恒 | 存在已就绪的独立责任和本轮可用 Agent 时，先交给 Agent，主智能体不能一边吸收多个可委派分支一边让负责人空闲 |
| 收窄主智能体责任 | 只默认保留未关闭决策、所有权冲突、共享运行环境、集成时机、最终取舍和授权动作 |
| 结果责任链 | Agent 工作包包含结果、退出条件、所有权、权威事实以及同一边界内可继续的核对、实现、修复和局部验证 |
| 执行检查点回填 | 主智能体准备开始新工作、消费结果或共享事实变化时读取必要状态，并在自己接手可委派工作前优先回填 `idle/done` 负责人 |
| 非阻塞派发 | 并行 `herdr agent prompt` 默认不使用 `--wait`；只有主智能体无可推进工作且下一步事实性依赖 Agent 时才等待 |
| 机制一致性 | Skill 生效期间的新并行责任默认进入现有 Herdr 工作面，不静默改用不可见内置子代理 |
| 持续遵循 | 规则置于 Skill 正文开头；阶段完成、Agent 返回、上下文压缩和自动续行都不是退出条件 |

这些规则不要求所有 Pane 始终繁忙。没有已就绪的真实责任、并发会造成双写，或者剩余工作依赖尚未关闭的决策时，Agent 可以空闲或被释放。
