# 研究记录规范

## 目标

`research/` 用于保存研究如何发生、结论如何形成以及后续改良如何改变原方案。研究记录是按时间累积的过程证据，不是持续覆盖成最新状态的使用说明。

面向使用和协作的当前有效规则写入 `skills/`、`agents/` 或 `docs/` 对应正式文档；研究目录保留形成这些规则的观察、分析、决策与迭代过程。

## 目录结构

每个研究主题直接建立在 `research/<topic>/`，不增加年月目录层级。时间信息写入主题 README 的时间线和各阶段文档标题。

主题目录至少包含一个 `README.md`。其他文件按发生顺序使用稳定的两位数字前缀，例如：

- `01-事实证据.md`
- `02-首次分析.md`
- `03-第一版设计.md`
- `04-首次运行评估.md`
- `05-第二版整改.md`

文件名称描述该阶段实际发生的研究活动，不预先创建空阶段，也不要求所有主题机械采用相同数量或名称。

## 时间线与阶段快照

1. README 使用按时间排列的索引，至少说明日期、阶段、对应记录和阶段结果。
2. 每次新的调查、运行评估或改良形成新的顺序文档；不要把后续发现打散后回填到早期专题文档。
3. 阶段文档形成后保留当时的事实、判断和版本边界。后续发现原结论不完整或错误时，新建记录说明证据、修正内容以及受影响的旧结论，并链接到前一阶段。
4. 同一次连续研究可以在一个阶段文档内按事件顺序补充；研究目标、事实基线、被评估版本或改良动作发生变化时，进入下一份文档。
5. 对仍在运行的 session，只分析读取时已经出现的事件。到达一次 rollout 文件末尾后立即形成阶段结论，不持续追踪文件增长；以后再次研究时再追加新记录。

## 内容边界

研究记录只保存会解释研究过程的材料：

- 研究对象、事实源、读取范围和必要的 session 标识；
- 观察到的行为及其先后顺序；
- 从事实推导出的模式、失败原因和阶段结论；
- 结论如何转化为下一版设计或改良；
- 实际执行的改良及其与上一阶段的对应关系。

以下内容不进入研究时间线：

- 仅用于确认设备链接、QA 接入、Codex 发现或文件读取是否生效的结果；
- 与研究结论无关的结构校验、普通回归输出和交付状态；
- 尚未执行的验证清单或推测性的未来待办；
- 凭据、业务正文、查询文本、完整 URL 或原始会话全文。

如果真实运行用于评估方案行为，并由此产生新的模式、失败原因或改良决策，则它属于研究活动；单纯确认某个版本已经被加载不属于研究活动。

## 结论进入正式产物

只有经过事实支持、会稳定改变智能体决策的规则才整理进 Skill、Agent 或正式协作文档。正式产物描述当前有效规则，不复述研究时间线；研究记录则通过阶段文档保留规则的来源和演进过程。

研究结论进入正式产物后，不删除或改写早期阶段以制造一条看似从未变化的正确路径。README 追加新的阶段索引，使读者能够依次看到初版判断、运行反馈和后续整改。
