# 2026-10-08：构建发布流程收敛

## 复用已有流程

用户要求签名、证书和 CI 采用确定性流程，否定先枚举大量异常分支的方案。读取 Glint、MoDu、QuotaPeek、PastePal 的产品 workflow，以及相关构建／打包入口，共同做法为：导入临时钥匙串、配置签名访问、调用项目打包入口、始终清理签名材料。

Glint 会话 `01a10a14-3af7-7372-8198-b06cdd1ae93c` 记录成功 Actions 运行 `37267542523`；本轮只重读源码，未重跑远端流程，也未读取真实证书材料。由此提炼命令失败即停止、清理仍执行、不降级身份的流程，删除多身份决策和异常分类。

## 从脚本模板到两条发布流程

用户要求可适配模板后，新增 `assets/build-dmg.sh`：Release 构建、组装、签名、读取实际版本与架构、生成 DMG、退出清理。项目差异集中在参数、构建与签名函数和固定命名；专用安装器沿用自身布局。

模板初版包含验签、镜像校验和挂载回读。隔离工具替身覆盖文件生命周期；独立临时 SwiftPM 样例用于真实签名与镜像检查。开发中发现 Swift 会向继承的临时目录写文件，遂将子进程 `TMPDIR` 纳入本次工作目录。挂载路径别名和 Bash 3.2 条件退出差异也曾带来规范化与断言修补，后随挂载检查整体移除。

用户随后指出签名与打包属于同一执行链，并要求参考 MoDu 版本规则。读取其 `AGENTS.md`、changelog、发布说明与验证脚本，将参考重组为版本准备、完整构建打包、GitHub Actions 三部分。

再按用户要求读取 MoDu 产品发布及 PastePal 站点流程，新增两个独立模板：产品由 tag 触发，签名打包后发布；站点按实际输入路径触发，复用已有构建和托管渠道。共享元数据与图标也可能影响站点，不能只过滤站点目录。GitHub 语法与 CLI 文档核实了 tag 不受路径过滤及 `--verify-tag` 的操作含义，技术链接保留在现行指引。

## 升版时机纠偏

起初提炼“新增功能升次版本、修复升补丁版本”，但“本次变化”容易被解释为每项任务都升版。用户明确一个版本可包含多个需求与修复，因此改为：日常开发、提交、合并和普通打包不升版；明确准备发布时，以上次正式发布为基线汇总整个批次，统一定版一次。

已计划未发布的版本继续积累变更；主版本由用户决定，构建号独立，正式发布后记录固定。未新增版本机器人或逐提交记账机制。

## 开发验证与日常执行分离

用户指出版本与 tag 应在推送前确认，构建成功后的文件断言属于重复检查，并要求排查整个 Skill。由此完成收敛：

- 删除日常脚本的 plist lint、版本格式断言、重复验签、镜像 verify、挂载回读，以及只服务这些步骤的状态和测试替身。
- 发布版本、目标提交与 changelog 在创建和推送 tag 前准备；Action 读取附注 tag 正文，删除下游版本检查、说明提取与中间 artifact。
- 站点完整输出由构建入口保证，workflow 使用日志和退出状态。
- 保留必需输入、失败传播、资源占用保护和半成品清理；用户明确占用时停下，由其手动处理，不自动卸载或终止进程。

附注 tag 的开发验证发现默认清理会移除 Markdown 标题，准备步骤因此使用 `--cleanup=verbatim`。上传无文件失败与 `--verify-tag` 分别属于动作失败语义和限制代建 tag，继续保留。

调整后的脚本完成过真实临时 SwiftPM／Apple Development／DMG 链路验证；这不代替已安装产品、远端 Actions 或真实 Codex 任务效果。最终源码见[构建打包](../../skills/apple-app-development/references/build-and-package.md)、[版本](../../skills/apple-app-development/references/versioning.md)与[Actions](../../skills/apple-app-development/references/github-actions.md)参考。
