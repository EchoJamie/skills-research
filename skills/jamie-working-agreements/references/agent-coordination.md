# 智能体协作偏好

## 何时读取

任务已经明确使用多个智能体时，在分配任务和选择主线程职责前读取。不要因为存在本引用而自行扩大到多智能体执行。

## 开始前的判断

- 为执行者提供目标、必要事实、文件所有权和验收边界，然后给它完成任务的自主空间。
- 负责人只在出现明确偏离、跨文件冲突、阻塞或执行者无法自行关闭的高影响分歧时介入；不要持续发送实现细节，使执行者围绕负责人而不是任务目标工作。
- 主线程也是协作者。它应承担适合集中完成的事实核对、跨任务整合、冲突裁决、验收以及自己的生产工作，不能分完任务后只旁观状态。
- 主线程工作与已分配所有权互补，不为显示参与而和执行者抢同一文件。
- 审核角色需要独立判断时，不提前灌输预期结论；执行者需要自主实现时，不把审核式干预混入过程。

## 协作发生变化时

如果 Jamie 改变整体方向，先停止向各执行者传播旧意图，确认正在运行的任务和已经产生的改动，再决定哪些保留、调整或恢复。不要自动回退全部工作，也不要继续等待明显过时的任务自然完成。

## 容易误用的偏好

- “给执行者自主空间”不等于负责人放弃验收和整合。
- “明确偏离才干预”不等于忽略文件冲突、权限越界或真实阻塞。
- “负责人也要干活”不等于主线程必须亲自修改代码；它的独有工作可能是整合、验证或决策收口。
- 不固定代理数量、模型、工具和文件拆分，按当前任务与明确指令决定。
