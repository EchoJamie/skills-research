## 1. 技能定位

| 编号 | 决策 |
|---|---|
| D-01 | 技能用于将已经确定的功能需求转换为符合当前代码与工程事实的实施方案、计划和详细任务单。 |
| D-02 | 技能的核心产物是规划和执行任务单，不是直接实施功能。 |
| D-03 | 详细任务单主要交给新会话或新窗口中的智能体自动执行，因此必须自包含且可独立验收。 |

## 2. 文档生成顺序

最终目录的阅读顺序不等于文档的生成顺序。技能必须按以下过程推进：

| 顺序 | 动作 | 产物或结果 | 断点 |
|---:|---|---|---|
| 1 | 读取已确定需求、设计材料、项目规范和当前代码 | 任务上下文与事实依据 | 需求来源或目标冲突时停止 |
| 2 | 核验当前实现、调用链、测试、数据、配置和交付约束 | 可供方案使用的当前事实 | 发现会改变功能目标的问题时停止 |
| 3 | 编写或修订实施方案与计划 | 方案草案 | 无 |
| 4 | 审核方案的事实准确性、内部一致性、范围和可实施性 | 审核记录与修订后方案 | 仍有阻断问题时不得拆分任务 |
| 5 | 生成《目标与实施边界》 | 面向人类的整体方案和规划总结 | 无 |
| 6 | 请用户确认方案基线 | 方案已确认，可拆分任务 | **强制用户确认断点一** |
| 7 | 根据已确认方案提出任务拆分草案 | 任务名称、目标、主要范围、前置依赖和验收出口 | 此时不生成详细任务单 |
| 8 | 请用户确认任务拆分 | 拆分方式已确认 | **强制用户确认断点二** |
| 9 | 生成详细执行任务单 | 可交给新会话执行的任务文档 | 无 |
| 10 | 审核任务覆盖、依赖、范围、停止条件和验收可判定性 | 修订后任务单 | 阻断问题无法从已确认方案中解决时停止 |
| 11 | 根据实际产物生成最终索引 | 可交付执行的计划文档集 | 技能结束，不自动开始执行 |

## 3. 强制用户确认断点

### 3.1 方案基线确认

生成任务拆分前，必须保证方案已经基本确定，并获得用户明确确认。

“基本确定”至少表示：

- 目标、范围与明确不做的事项已经清楚。
- 当前实现与主要缺口已按当前代码核验。
- 会改变总体实现路径的技术与产品选择已经确定。
- 安全、数据迁移、兼容、发布与验收方向没有未解决的阻断性歧义。
- 剩余未决事项不会改变总体方案和任务边界。

用户未明确确认时，技能必须停在方案阶段，不得以“默认认可”、“无异议”或对方没有回复作为通过依据。

### 3.2 任务拆分确认

用户确认方案后，技能先只生成任务拆分草案，让用户审核：

- 任务是否拆得过细或过粗。
- 是否遗漏了方案的关键实施内容。
- 本应形成一个完整闭环的内容是否被机械拆开。
- 前置依赖是否真实且必要。
- 每个任务的验收出口是否足以侜人判断。

只有用户明确确认拆分方式后，才能批量生成详细任务单。

## 4. 任务依赖与并行

| 编号 | 决策 |
|---|---|
| D-04 | 计划产物只记录任务的前置依赖，不记录“并行组”、“可与某任务并行”等预设调度结论。 |
| D-05 | 执行时，智能体根据哪些任务的前置依赖已达成，动态判断可否并行。 |
| D-06 | 即使多个任务同时满足依赖，执行者仍应根据当前工作树、文件所有权和冲突风险决定是否真正并行。 |

## 5. 阶段与目录结构

| 编号 | 决策 |
|---|---|
| D-07 | “阶段 / 任务”二级目录不是必选结构，不应由技能模板预先强制。 |
| D-08 | 只在方案本身存在自然阶段、明确阶段出口，或前一阶段会改变后续代码基线时，才引入阶段。 |
| D-09 | 即使方案有阶段，任务数量较少时也可以保持扁平目录，在任务元信息中记录所属阶段。 |
| D-10 | 最终目录只包含实际需要的产物；不为了形式完整生成空的确认事项、阶段目录或其他文档。 |

## 6. 任务拆分原则

| 编号 | 决策 |
|---|---|
| D-11 | 不按数据库、后端、前端、测试等技术层机械拆分任务。 |
| D-12 | 一个任务应能在一个新会话中独立理解、实施和验收，并形成有意义的完整结果。 |
| D-13 | 多个技术层如果必须一起修改才能形成有效行为，可以保留在同一任务中。 |
| D-14 | 只有当内容具有不同前置依赖、稳定修改范围并且能够独立验收时，才优先拆成不同任务。 |
| D-15 | 不使用固定人天、固定文件数量或“一个模块一个任务”作为机械拆分规则。 |

## 7. 术语决策

| 编号 | 决策 |
|---|---|
| D-16 | 不使用 `G`、`WP` 等不利于人类审核的缩写。 |
| D-17 | 使用“确认事项”表达必须由用户或专业负责人决定的内容。 |
| D-18 | 使用“任务”或“执行任务单”表达交给新会话执行的单元。 |
| D-19 | 可以使用“阶段 1”、“阶段 2”表达方案中真实存在的实施阶段，但不使用 `P1` / `P2` 这种容易与优先级混淆的缩写。 |
