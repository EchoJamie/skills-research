# 《目标与实施边界》模板

该文档在开发工具包独立审核通过后最后生成，是对已确认方案与当前工具包的人类可读总结，不引入新设计。

```markdown
# <功能名称>目标与实施边界

> 来源方案：实施方案与计划 vX.Y
> 方案 SHA-256：<digest>
> 当前开发工具包 SHA-256：<digest>
> 最后工具包审核记录：<相对路径>
> 形成日期：YYYY-MM-DD

## 1. 建设目标

用面向人类评审者的语言说明为什么做、完成后解决什么问题、用户或系统能看到什么结果。

## 2. 实施范围

### 包含

### 不包含

### 必须保持不变

## 3. 核心实施路径

概括关键节点和事实性依赖，不复制全部任务细节。已确认方案存在独立交付流时，概括各自出口、共享契约和汇合门槛；不存在时不人为规定并行组。

## 4. 关键约束

汇总数据、安全、兼容、权限、发布、迁移和回滚等决定性边界。

## 5. 完成与验收

列出可观察的整体验收结果和必须取得的证据。

## 6. 风险与保留事项

只保留已确认且已在任务中落实的非阻断风险，以及明确的授权外事项。

## 7. 开发工具包入口

- 工具包目录：`开发工具包/`
- 使用方式：在新会话中提供该目录，由执行者读取 `README.md` 和任务单，并根据事实性前置依赖安排执行。
```

## 一致性检查

- 目标、范围和保持不变行为与已确认方案一致。
- 核心路径与当前工具包任务及依赖一致。
- 验收没有弱于方案或工具包。
- 没有新增方案决策、任务或权限。
- 所列风险已在对应任务中落实。
- 路径为可分享的相对路径，不泄露本机绝对路径。
