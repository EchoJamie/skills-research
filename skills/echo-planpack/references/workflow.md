# 实施规划工作流

## 1. 状态与允许动作

| 当前状态 | 进入条件 | 允许动作 | 离开条件 |
|---|---|---|---|
| 待规划 | 需求功能与关键产品决策已经确定 | 只读核验工程事实、来源和送审范围 | 高影响实施决策已识别 |
| 实施决策对齐 | 仍有会重写方案主体或任务拆分的高影响选择 | 在对话中给出精简选项、推荐和代价，只请求必要决定 | 用户决定已取得，或确认不存在此类未决项 |
| 方案编制 | 高影响实施决策已对齐 | 创建或承接首版方案 | 方案候选版本完成 |
| 方案自检 | 候选方案完成 | 检查需求覆盖、事实、范围、契约和验收 | 自检无已知阻断 |
| 送审准备 | 方案自检完成 | 检查来源适用范围、保持不变清单、事实索引、入口盘点和验收追溯 | 没有明显送审准备缺口 |
| 方案独立审核 | 方案对象已冻结并计算摘要 | 独立审核者只读审核并新建记录 | 审核记录有效产生 |
| 方案修订 | 审核不通过 | 创建新的方案版本 | 新版本完成并重新自检 |
| 待用户确认 | 方案独立审核通过 | 请求用户确认精确版本与摘要 | 用户明确确认或提出修改 |
| 方案基线已确认 | 确认记录已创建 | 生成当前开发工具包 | 工具包完整 |
| 工具包自检 | 当前工具包完成 | 检查自包含性、覆盖、依赖、边界和验收 | 自检无已知阻断 |
| 工具包独立审核 | 工具包冻结并计算整体摘要 | 独立审核者只读审核并新建外部记录 | 审核记录有效产生 |
| 工具包修订 | 审核发现工具包问题 | 更新或重新生成当前工具包 | 重新自检和送审 |
| 方案问题待决定 | 工具包审核发现已确认方案问题 | 只报告，不改方案或工具包 | 用户决定是否重新打开方案 |
| 规划完成 | 工具包审核通过 | 生成《目标与实施边界》并做一致性检查 | 向用户交付路径和摘要 |

不要跳过方案独立审核、用户方案确认或工具包独立审核。实施决策对齐只在存在会导致主体重写的未决选择时触发，不是固定确认断点；送审准备和自检也不是独立审核。

## 2. 文件结构与生命周期

```text
<功能规划目录>/
├── 实施方案与计划_v1.0.md
├── 实施方案与计划_v1.1.md
├── 方案审核记录/
│   ├── YYYYMMDD-01-方案初审.md
│   └── YYYYMMDD-02-用户确认方案基线.md
├── 开发工具包/
│   ├── README.md
│   └── 任务-01-<任务名称>.md
├── 开发工具包审核记录/
│   └── YYYYMMDD-03-开发工具包初审.md
└── 目标与实施边界.md
```

这只是默认平面结构，不强制阶段子目录。只有内容规模和边界真正需要时才增加层级。

### 方案

- 实质修改形成新版本，旧版本保持不变。
- 已送审或已确认的方案不原地修改。
- 用户确认以外部记录为准，方案正文不回写“已确认”状态。

### 开发工具包

- 只保留当前有效副本，不生成 `v1`、`旧版`、`backup` 等历史副本。
- 每一轮审核期间冻结；审核轮次之间可以更新或重新生成。
- 审核记录、执行记录和临时文件不放入工具包。
- 公开分享工具包时，只需分享 `开发工具包/` 本身。

### 审核记录

- 审核者负责创建方案/工具包审核记录。
- 规划者只负责根据用户明确表达创建用户修改意见或用户确认方案基线记录。
- 审核记录只新增，不覆盖。

### 送审范围与事实证据

- 默认作为方案章节和审核交接内容，不强制增加正式文件。
- 规模较大时允许形成当前过程资料，但必须位于开发工具包之外，不得成为工具包的执行依赖。
- 事实索引用于定位和判定证据是否变化，不能替代审核者的独立验证。
- 关键事实使用稳定编号；路径、符号、核验方式、日期和内容指纹变化时，更新其状态并标记受影响设计与验收。

## 3. 来源层级

| 类型 | 作用 | 使用约束 |
|---|---|---|
| 规范性来源 | 定义本期必须实现的需求、目标、产品决策和强制工程边界 | 仅包含已经确定且适用于本期的内容及有约束力的组织/项目规则 |
| 兼容约束 | 限定不能破坏的既有契约或相邻方案条目 | 必须写明具体适用章节、规则或行为，不得整份笼统引入 |
| 事实性来源 | 证明当前代码、配置、数据结构、运行和仓库状态 | 只能证明现状，不能反推新需求 |
| 历史参考 | 帮助理解背景和曾经方案 | 除非被当前决策明确采纳，否则不具有规范效力 |

开发工具包以用户确认的具体方案版本为唯一方案规范来源；当前代码、项目规则以及前置任务应产生的可验证事实只能用于核验定位和基线漂移。《目标与实施边界》只总结已确认方案和已审核工具包，不新增设计来源。

来源冲突时不要静默取舍。记录冲突、影响和需要谁决定。

## 4. 独立审核资格

正式独立审核者必须：

- 是与规划会话隔离的新会话或最小上下文子代理；
- 能读取限定来源；
- 能在指定目录新建审核记录；
- 对规划者提供的自检发现或已知风险只作为待核验线索，能够独立判断其真伪、严重性和处置；
- 不接受预期结论、通过压力或指定修复方案作为判断前提；
- 不修改被审核对象。

只能继承规划会话完整历史的子代理不合格。其意见可以作为规划者自检补充，但不能产生正式通过结论。

### 审核会话生命周期

- 方案首次送审时创建一名合格独立审核者。
- 方案产生新版本、生成开发工具包或工具包更新后，默认向同一审核会话追加审核任务。
- 持续复用不破坏独立性：审核者仍与规划者隔离，对规划者给出的已知线索独立取证和判断。
- 原审核者不可继续、上下文丢失、独立性受损，或规范来源、目标范围、主要模块边界实质变化时，才创建新的审核者并记录原因。
- 从方案切换到开发工具包属于新的审核对象，但不是自动重建事实基线的理由。默认由方案审核者审核方案到任务的转换。
- 只有原审核者不可继续、独立性受损、上下文丢失、用户明确要求新审核者，或工具包引入方案未覆盖的高风险事实时，才为工具包建立新审核者，并记录原因和需重建的事实范围。

### 复审强度

复审始终完整检查当前对象的内部一致性，并逐项关闭上一轮发现。工程事实重点复核本轮变化、受影响事实编号和直接依赖范围，不默认从零重新调查整个授权仓库。

开发工具包审核首先检查确认方案到任务、依赖、权限和验收的转换。未新增事实断言、相关指纹未变化且未命中高风险复查条件时，复用方案审核阶段已经独立核验的事实，不重新调查代码。审核者不得把个人偏好、通用最佳实践或新的治理产物作为工具包阻断依据。

任一条件成立时重新执行相应范围的完整事实调查：

- 规范性来源或兼容约束发生变化；
- 目标、范围、关键契约、验收或主要模块边界发生变化；
- 事实证据内容指纹失效或工作区相关文件发生变化；
- 上一轮发现事实索引遗漏、错误或无法证明完整性；
- 安全、租户、迁移或跨服务风险无法被现有影响范围可靠封闭。

## 5. 异常出口

### 无合格审核者

直接在对话中输出可复制的新会话交接提示词，并停止在待审核状态。除非用户明确要求留档，不创建交接提示词文件，也不要继续生成后续产物。

### 审核对象变化

若开始与结束摘要不一致，本轮审核失效。修订完成后重新冻结并送审；复审仍按“当前对象完整一致性检查 + 变化及受影响事实复核”执行，命中完整事实调查条件时再扩大核验范围。

### 工具包审核发现方案问题

不要修改已确认方案。报告问题、证据、影响和需要的用户决定，停止工具包循环。用户允许重新打开方案后，创建新方案版本并重新经过方案审核和用户确认。

### 审核提出新的范围或治理要求

若建议无法追溯到规范性来源、已确认方案、直接工程事实或未控制的安全/数据风险，不得作为阻断问题。把它记录为改进建议或待用户决定的范围扩展候选，不要求规划者为了通过而实现。必需修正只描述必须恢复的约束或可观察结果，不强制指定某个实现结构、目录或辅助产物。

### 缺少事实或权限

影响核心判断时归为事实阻塞并停止。不要编造接口、表结构、路径、运行结果或前置任务产物。

### 修订循环失去进展

任一条件触发熔断：

- 同一根因经过两次方案或工具包修订仍阻断；
- 已解决问题再次出现；
- 规划者和审核者对规范性来源存在实质分歧；
- 缺少权威事实或权限；
- 修正要求改变已确认方案；
- 送审对象反复不稳定；
- 只能降低验收或缩小既定范围才能通过。

熔断报告应包含根因、已采取处理、当前证据、仍阻断原因和所需事实或决定。

## 6. 完成条件

同时满足下列条件才算规划完成：

- 具体方案版本的独立审核结论通过；
- 用户明确确认同一方案版本及摘要，确认记录存在；
- 当前工具包自包含且不含实际代码；
- 当前工具包独立审核结论通过，开始与结束摘要一致；
- 非阻断风险已落实到任务；
- 《目标与实施边界》与方案、工具包一致；
- 没有未解决阻断问题或事实阻塞。
