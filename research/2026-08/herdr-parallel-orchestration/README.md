# Herdr 并行编排 Skill 研究

> 研究日期：2026-08-29
> 样本 session：`01a042b3-49f6-76d0-8acd-98c6c855d826`
> 当前状态：已形成开发区 Skill 并通过静态校验；样本 session 仍在继续，研究按事件顺序延续且不做文件哈希锚定

## 研究目标

从一个长时间、多阶段的真实开发 session 中，提取“主智能体持续执行、Herdr 可见 Agent 局部加速”的并行模式、性能瓶颈和失败护栏，形成一份不重复 Herdr 命令手册的高层并行编排 Skill。

本研究采用观察调研方式：先保留原始 session 的事实时间线，再区分成功模式、失败模式和一般化决策，最后制作 Skill。研究记录保留过程；正式 Skill 只包含会改变未来调度行为的稳定规则。

## 研究边界

- 主要事实源是本机 Codex rollout JSONL，不以回忆或最终总结替代原始事件。
- 重点分析 Herdr 的 Tab、Pane、Agent、派发、等待、直接交接、扩缩容和收口行为；Dolphin 阶段 A 的业务实现只作为调度上下文。
- 原 session 同时使用过 Herdr 可见 Agent 和 Codex 内置子代理，因此不能把全部产出归因于 Herdr。
- 原 session 包含用户提供的敏感认证材料。本研究不复制凭据、业务正文、查询文本、完整 URL 或原始会话输出。
- 当前只有一个复杂样本；一般化结论需要后续新会话继续验证。

## 后续验证

1. 在新的 Herdr 会话中，验证主智能体在派发局部工作后仍持续完成自己的主线责任，而不是转入观察和等待。
2. 验证 Agent 获得完整局部责任后，能够自行审查、规划并持续推进，不需要主智能体逐项续派。
3. 验证共享契约、全量测试等全局影响动作由主智能体择机执行，没有被当作普通 Agent 工作包派发。
4. 对比“反复状态轮询”和“主智能体只在自身自然检查点读取必要状态”两种方式的协调开销、首个可验收出口时间与返工次数。
5. 使用第二个非 Dolphin 项目样本，检查局部唯一所有权能否在不增加通用检查层的情况下避免冲突。
