# macOS 实现与验证流程

用于原生窗口、焦点、状态恢复和常驻行为的开发与修复。预期界面行为由 [交互指引](interaction-preferences.md) 定义，功能和设置语义由 [软件设计指引](software-design-preferences.md) 定义；本文负责定位问题、落实实现并验证结果。

按下面的顺序处理本次问题，不把开发验证加入每次构建、打包或启动应用的执行路径。

## 1. 复现并定位责任位置

先复现用户的完整操作链，明确实际失败在哪一步。应用到前台、窗口激活和输入控件获得焦点是不同状态；跨应用问题在实际目标应用中复现，本地替代页面只能提供局部证据。

| 问题类型 | 优先查看的位置 |
|---|---|
| Dock、窗口激活或返回异常 | 窗口打开／关闭路径、统一激活策略；AppKit／SwiftUI 项目的 `LSUIElement` 与 activation policy |
| 默认蓝色框或输入焦点异常 | 初始焦点分配、键盘焦点环、默认按钮样式和业务选中态，先区分实际来源 |
| 设置页裁切、空白或尺寸塌陷 | 自然窗口尺寸下的布局、内容自适应和滚动区域 |
| 恢复成功但界面仍报错 | 当前操作结果与负责数据、错误、过期标记和刷新状态的既有对象 |
| 输入源、菜单栏或宿主集成异常 | 当前系统状态与真实宿主行为；缓存、注册或选中标记不能代替实际效果 |
| 常驻资源占用异常 | 空闲 CPU、唤醒、内存，以及窗口关闭后仍运行的后台任务 |

## 2. 在负责该行为的位置做最小修改

- **窗口与 Dock**：复用窗口生命周期和统一激活策略，不为每个窗口增加 Dock 状态或进程。按界面用途使用 `.regular`、`.accessory` 或框架对应机制，保留快捷面板与输入法的原输入目标。
- **标准命令**：复用系统菜单、标准控件与框架已有命令机制，菜单和快捷键连接同一操作；自定义按键处理只接管工具实际需要的部分，不为每个标准快捷键另建全局监听或平行实现。
- **初始焦点**：优先删除多余的自动聚焦；不定时清焦点、不在每次重绘时抢焦点，不增加平行的焦点状态。
- **状态恢复**：由既有状态所有者依据实际操作结果一起更新数据与反馈。关闭、刷新和恢复入口不依赖失败业务先成功；异步等待应能结束，不能因截图或 AX 等局部故障卡住整个应用。
- **后台工作**：复用现有生命周期，窗口隐藏后停止仅服务该界面的定时任务；不把无需常驻的数据全部装入内存。

根因未确认时一次验证一个假设，保留正常工作的键盘和输入行为。不因单条系统警告反复重装、清缓存或改系统配置；确认问题在宿主或系统路径时，如实保留该边界。

## 3. 按改动选择真实操作验证

只覆盖本次改动相关且产品实际支持的场景，预期结果按交互指引判断：

| 改动 | 验证操作 |
|---|---|
| Dock／窗口激活 | 从状态栏打开；切到其他应用后返回；最小化后恢复；关闭部分窗口、最后一个窗口并重新打开 |
| 初始焦点 | 首次打开、切页和重开；随后主动键盘导航、文本输入并执行原有确认操作 |
| 标准菜单与快捷键 | 从菜单及对应按键执行设置、关闭、退出、隐藏等相关命令；在输入框中编辑文本，确认自定义按键不抢占标准操作 |
| 设置布局与保存 | 从菜单和快捷键打开、重复打开及关闭后重开；以自然尺寸切换分类、滚动并修改代表性选项，确认布局可用且保存／生效反馈符合约定 |
| 语言／明暗适配 | 切换实际支持的语言，检查菜单与界面一致性及长文本布局；切换系统、浅色、深色模式，观察窗口和图标表现，重开后确认手动选择保留 |
| 跨屏交互 | 在 A 屏使用后移到 B 屏，执行第一次呼出、选择或输入 |
| 状态恢复 | 复现失败后完成恢复，观察数据与提示更新，并操作关闭、刷新和返回入口 |
| 系统集成 | 在实际宿主中激活并输入；跨应用操作回到原输入目标 |
| 常驻行为 | 观察空闲、操作中和窗口关闭后的资源占用与任务生命周期 |

单元、固定尺寸和离屏测试用于受控验证，不能替代真实 Dock、焦点或宿主操作。确定性脚本按开发阶段测试与运行时职责分工处理，不另加重复断言。

## 4. 说明结果并收尾

报告实际修改、已执行的测试与真实操作，以及尚未覆盖的环境；不将局部通过表述为全产品验收。截图、录制和诊断文件按本次问题临时使用，完成判断后清理，只保留未解决问题或明确交付要求需要的材料。

需要交付安装包时再读取 [构建打包指引](build-and-package.md)；窗口修复本身不要求加载或执行整套打包与 CI 流程。
