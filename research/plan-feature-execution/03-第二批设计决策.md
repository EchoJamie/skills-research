> 后续变更：对抗复核建议逐项确认后形成了 [06-第三批设计决策.md](06-第三批设计决策.md)。其中取消了任务执行技能，保留实施规划和独立审核两个核心技能；同时补充了审核独立性、方案版本、工具包生命周期和分享边界。与本文件冲突时，以第三批决策为准。

## 1. 正式文档生成时间线

| 编号 | 决策 |
|---|---|
| D-23 | 《实施方案与计划》是整个流程最先生成的正式产物。 |
| D-24 | 《实施方案与计划》可能经过多次修改，不能因为已经生成首版就进入开发工具包阶段。 |
| D-25 | 方案的初审、复审和后续审核记录放在独立的“方案审核记录”目录中，不把审核意见直接混入当前方案正文。 |
| D-26 | 方案基本确定、独立审核没有未解决阻断问题并获得用户明确确认后，才形成方案基线。 |
| D-27 | 方案基线确认后直接生成完整开发工具包，不再先生成“任务拆分草案”。 |
| D-28 | 不再设置“用户确认任务拆分”或“用户确认开发工具包”的常规确认断点。 |
| D-29 | 《目标与实施边界》最后生成，用于向人类概括已经确认的方案和已经审核的开发工具包，而不是用来提前决定任务拆分。 |

修正后的主要时间线为：

```text
生成或修改《实施方案与计划》
          ↓
独立审核并生成方案审核记录
          ↓
根据审核意见继续修订和复审
          ↓
用户确认方案基线
          ↓
生成完整开发工具包
          ↓
自检并委托独立审核
          ↓
处理审核发现的实施层问题
          ↓
审核无未解决阻断问题
          ↓
最后生成《目标与实施边界》
```

## 2. 用户确认断点

| 编号 | 决策 |
|---|---|
| D-30 | 唯一常规用户确认断点是《实施方案与计划》基线确认。 |
| D-31 | 开发工具包属于已确认方案的派生产物，正常情况下通过自检和独立审核闭环，不再要求用户重复确认。 |
| D-32 | 如果开发工具包审核发现必须改变已经确认的功能目标、范围、非目标、总体技术路径或其他实质性方案决定，必须停止自动修订并重新请求用户确认。 |

## 3. 分角色技能组

| 编号 | 决策 |
|---|---|
| D-33 | 当前能力应设计成一组技能，由不同角色在不同阶段使用，而不是让一个技能在同一上下文中同时扮演规划者、审核者和执行者。 |
| D-34 | 技能组至少包含实施规划、独立审核和任务执行三类角色能力。 |
| D-35 | 实施规划角色负责主流程协调、方案编制与修改、开发工具包生成与自检，以及最后生成《目标与实施边界》。 |
| D-36 | 独立审核角色必须运行在另一个智能体上下文中；方案审核至少使用另一个会话，开发工具包审核由实施规划角色委托子代理完成。 |
| D-37 | 任务执行角色主要在新会话或新窗口中读取一份详细任务单并自动执行。 |

技能按角色拆分，不按每个阶段、每份文档或每次审核机械拆分。后续可以根据正式制作和测试结果决定三个角色是作为独立技能安装，还是组合成统一技能包。

## 4. 方案审核记录的所有权

| 编号 | 决策 |
|---|---|
| D-38 | “方案审核记录”目录中的初审、复审等智能体审核文件由实际承担审核的另一个智能体自行创建。 |
| D-39 | 实施规划角色不能预先生成初审、复审文件，也不能替独立审核者决定实际文件名。 |
| D-40 | 审核者应根据当前目录内容和本次审核性质确定文件名，历史审核记录保持独立留存。 |
| D-41 | 实施规划角色读取审核记录后修改当前《实施方案与计划》，但不覆盖或回写审核者的历史记录。 |

例如，目录可能随着实际审核过程逐步形成：

```text
方案审核记录/
├── 20260813-01-方案初审.md
├── 20260813-02-用户修改意见.md
└── 20260814-03-方案复审.md
```

该结构是审核过程产生的结果，不是实施规划角色在开始时生成的固定空目录模板。

## 5. 开发工具包审核闭环

| 编号 | 决策 |
|---|---|
| D-42 | 实施规划角色生成开发工具包后必须先自检，不能未经检查就直接送审。 |
| D-43 | 自检完成后，由实施规划角色委托独立审核子代理进行审核。 |
| D-44 | 开发工具包审核必须限定方案来源：以用户已经确认的《实施方案与计划》为唯一规范性方案来源。 |
| D-45 | 审核者可以读取当前代码和项目规范验证事实，但不能据此自行引入新需求、替换技术方案或扩大已确认范围。 |
| D-46 | 审核发现可在已确认方案内解决的实施层问题时，由实施规划角色修改工具包，再次自检并重新送审。 |
| D-47 | 独立审核没有未解决阻断问题后，实施规划角色直接进入《目标与实施边界》的生成，不增加一次用户确认。 |

## 6. 继续有效的首批决策

以下首批决定没有被本轮调整改变，继续有效：

- 技能只在需求功能已经确定、需要转为具体实施计划时触发。
- 执行任务单面向新会话或新窗口，必须自包含并可独立验收。
- 产物只表达事实性前置依赖，不预设并行组；执行时再根据依赖、工作区和冲突风险决定并行。
- 阶段和“阶段 / 任务”二级目录按实际方案决定，不强制使用，不为了形式完整而过度拆分。
- 不使用 `G`、`WP`、`P1`、`P2` 等不利于理解或容易与优先级混淆的命名。
- `租户切换问题与处理待办_20260812.md` 不属于当前技能范围。
- 《目标与实施边界》继续保留，但生成时间调整为整个规划流程的最后阶段。
