# Herdr 可视化并行编排

用户显式调用本 Skill 后，主智能体必须在后续任务处理中持续遵循本 Skill 的引导，以保持高效的并行编排；不得因阶段完成、Agent 返回、上下文压缩或自动续行而自行停止使用。只有用户明确要求不再使用本 Skill 时，才退出本 Skill 的编排约束。

在复杂实施、调研或验收任务中，让当前主智能体与 Herdr 中用户可见的 Agent 共同持续推进目标。主智能体和 Herdr Agent 都是能够审查事实、规划步骤并完成工作的完整智能体；该 Skill 约束责任分配与自然交接，不建立按时间轮询或追求 Pane 占用率的机械调度流程。

若决定使用多个智能体，默认采用 Herdr 可视化协作，不自行委派不可见的内置子代理。具体 Herdr 命令、安全约束和状态语义以当前环境中的 `herdr` Skill 与本机 CLI 为准。

## 判断与分工

1. 先判断任务是否真的存在可以同时推进的独立工作。单智能体足以高效完成时，当前主智能体直接做，不为形式启动 Herdr。
2. 决定使用多智能体时，完整读取并遵循当前可用的 `herdr` Skill，并按其要求确认 `HERDR_ENV=1`。环境不可用时，主智能体继续完成仍可完成的工作并报告限制，不静默改用内置子代理。
3. 只有用户明确要求，或适用的必需工作流指定了其他精确 Agent 机制时，才偏离 Herdr 默认。已有不可见任务让原负责人完成当前工作包，后续任务改走 Herdr；不打断、复制或迁移半成品。
4. 并行不扩大提交、部署、数据写入、外部操作或其他授权边界。

## 工作守恒与责任链

主智能体根据目标、当前事实、现有工作和授权边界自行审查怎样分工；这属于正常推理，不增加独立检查阶段。采用以下工作守恒原则：只要存在已就绪、互不冲突、能独立推进目标的责任，并且本轮 Herdr Agent 已处于 `idle` 或 `done`，就先把该责任交给可用负责人；主智能体不得一边保留多个可委派责任，一边让本轮负责人空闲。

这不要求所有 Pane 始终繁忙。没有已就绪的真实责任、继续并发会造成双写或中间态误判、或者剩余工作确实依赖主智能体尚未关闭的决策时，负责人可以空闲或被释放；不要制造旁支调研、重复产物或额外检查来填充工作面。

主智能体始终保留并执行至少一项直接推进目标的具体责任，不能因派发而退化成观察者；但“保留一项”不能成为吸收全部关键路径的理由。它只默认保留下列不可委派责任：

- 尚未关闭的目标级决策、共享契约冲突和跨责任所有权裁决；
- 会改变其他负责人前提的集成时机、共享运行环境、性能负载和全量验证结论；
- 全局 Diff 与最终取舍，以及需要单独授权的 Git、交付、外部操作和数据变更。

契约或方向一旦冻结，其在不同模块中的实现、公共配置的独立传播、局部迁移和对应测试不再因“跨模块”自动归主智能体；只要能建立不重叠所有权和稳定出口，就应成为独立责任链。全局动作的时机和结论仍由主智能体负责，命令可以放在可见命令 Pane 中运行。

给 Agent 的工作包应是一条足够长的结果责任链，而不是一个容易立即耗尽的微步骤。调用 `herdr agent prompt` 时说明：

- 最终结果和退出条件；
- 文件、模块、事实或环境的所有权范围；
- 已关闭的关键决策、权威来源和授权边界；
- 在同一所有权内可以自主继续的相邻工作，例如事实核对、实现、局部修复、局部验证和稳定交接产物。

负责人在责任链内自行决定步骤并持续推进到退出条件，不必每完成一个小项就等待续派。一个紧密耦合的责任只设一个负责人；做到一半不换人，偏离时只纠正错误事实、目标或边界。完成后若转入不同领域，主智能体先调整 Agent 名称和可见责任。

## 已验证的失效护栏

- **并行派发不得占住主线**：用于并行责任链的 `herdr agent prompt` 默认不使用 `--wait`；提交成功后，主智能体立即继续自己的责任。只有主智能体已无可推进工作，并且下一步事实性依赖该 Agent 的结果或阻塞信息时，才使用等待。等待是依赖成立后的例外，不是派发的默认组成部分。

## 派发、回填与交接

- 建立工作面时，先派发当前已经就绪且互不冲突的责任链，再继续主智能体自己的不可委派主线；不预占仍被 Gate、决策或上游产物阻塞的未来任务。
- Herdr 不会把邻居 Agent 的完成或阻塞主动注入当前会话。主智能体不按时间轮询，但在准备开始一个新的工作包、消费完一个 Agent 结果、共享事实发生变化或下一步真实依赖 Agent 时，必须形成一次执行检查点：读取本轮必要状态，整合已完成结果，并在自己接手新的可委派工作前优先回填 `idle` 或 `done` 负责人。
- 状态读取和等待用于发现事实，不代替回填，也不连续重复相同检查。
- 新出现的独立责任默认进入现有 Herdr 工作面。Skill 生效期间不得把新并行工作交给不可见内置子代理；只有用户明确要求或必需工作流指定精确机制时例外，并在使用前向用户说明该例外。已有不可见任务完成当前包后，后续责任转回 Herdr。
- 多智能体发生冲突时，优先判断责任划分、所有权或先后依赖是否错误，重新分工后让原负责人继续；不要用更频繁的扫描、轮询、锁或事后重跑掩盖分配问题。
- Agent 间需要衔接时，让下游直接读取上游 Agent 的原始结论或稳定产物，主智能体不充当逐条转述中继。
- 用户目标、公共契约或全局事实变化时，由主智能体及时通知受影响负责人。负责人基于新事实重新审查责任路径；仍然有效的工作保持原负责人，不能继续沿用已经失效的前提。

局部负责人完成与其责任相称的局部验证；主智能体只在自然集成点执行必要的全局验证，不机械重复每个 Agent 已完成的检查。若一项工作无法在不增加复杂协调的情况下独立闭环，就留给主智能体或并回它所依赖的责任。

## 可见工作面

按责任或生命周期组织 Tab，使用稳定、可辨识的 Agent 名称。只在现有工作面难以阅读或新工作具有独立生命周期时新增 Tab；不以占满 Pane 为目标。检查工作量时只统计本轮拥有的工作面，不把其他 workspace 的历史 `idle` Agent 当成本轮容量或失败证据。

启动和控制细节遵循 `herdr` Skill，不在此复制命令、审批、沙箱或状态判断规则。

## 用户可见性

建立或调整工作面后，向用户简要报告主智能体正在亲自推进的工作、Herdr Agent 的局部所有权和交接出口。之后只在真实里程碑、需要用户决策或授权的阻塞、运行验证结论、用户询问或拓扑变化时更新。

报告必须区分：Agent 自报、主智能体静态复核、自动化测试、真实服务或环境验证。用户要求每次性能测试后报告时，测试一结束就单独报告，不能用预检或普通单测替代。

## 完成与清理

主智能体在合适时机整合结果、执行与风险相称的全局验证并给出最终结论。本轮 Agent 完成后，若没有已就绪或可合理预期的后继责任，就释放或清理本轮创建的资源；不关闭用户或其他客户端创建的工作面。

最终交接区分 Agent 自报、主智能体静态复核、自动化测试和真实环境验证，并列出未验证项。Herdr 生命周期状态不等于任务正确完成。
