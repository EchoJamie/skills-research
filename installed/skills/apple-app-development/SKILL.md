# Apple App Development

以下是本 Skill 的应用开发默认约定；后续明确的新指令优先。只应用与当前任务有关的规则。

## 始终保留的约定

- 所有 Apple 应用的本地调试、Release 和分发版本均使用现有 Apple Development 身份，不自动改成 Developer ID、Apple Distribution、ad hoc 或无签名，也不反复要求购买会员或确认这个选择。
- 用户要求“打包”且未指定类型时，交付 Release；智能体为开发、测试或验证自行构建时才默认使用 Debug。应用内的运行时调试开关不决定构建配置或数据目录。
- 产品版本采用 `x.y.z`，按发布批次统一确定；开发、提交、合并和普通打包不自动升版。主版本变更由开发者明确决定，应用与包使用同一版本来源，构建号独立。复用项目已有打包入口、产物目录和命名，不为普通打包增加交付层级。
- 编译缓存可以保留复用；过程材料默认用完清理。普通检查直接执行并报告结果，不默认生成构建报告、检查 JSON、截图档案或证据目录；长期保留需要明确的后续用途，不能仅以“以后可能有用”或“证明检查过”为理由。
- macOS 状态栏菜单／popover 可以没有 Dock 图标；设置、图标整理等独立业务窗口打开时必须有应用的 Dock 入口。临时快捷面板、输入法候选窗和截图浮层保留各自的焦点约定。
- 新建应用和设计、开发相关模块时，主动落实界面语言（i18n）、明暗模式和版本展示，不加入意见反馈入口；macOS 标准菜单、窗口和编辑快捷键也是默认需求，无需用户逐项提出。
- 设置界面采用现代简洁风格，需要分类时使用左侧导航与右侧内容区；禁止传统大图标顶部分类的偏好窗口风格。
- 界面首次显示时，普通可点击组件不默认显示蓝色焦点框；用户主动键盘导航时保留清楚的焦点提示，已有明确的打开即输入行为继续保留。
- 产品围绕日常任务取舍：核心任务路径直接、清楚，设置表达真实含义，自动维护减少负担并尊重当前操作。具体设计与交互按需读取下方参考。
- 确定性流程在开发或修改后验证；日常执行由各步骤保证自身结果，调用方使用日志和退出状态，不重复断言上游结果。发布条件在推送 tag 前确认，资源占用保护和失败清理仍保留。
- 签名成功、镜像完整、实际安装运行和远端发布是不同证据。签名约定不改变平台或渠道的真实技术限制；打包不隐含安装替换、提交、推送或发布授权。
