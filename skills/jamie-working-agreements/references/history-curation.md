# 历史纠偏筛选

## 何时读取

需要从新历史对话补充、修订或删除个人习惯时读取。它只服务于偏好库维护；普通任务运行本技能时不要回查全部历史。

## 证据分级

高置信度依据必须是 Jamie 在原始对话中的直接输入，并且实际形成了转折，例如：

- 主动打断正在执行的路径；
- 明确否定方向、范围、方法或角色理解；
- 把关注点重新指向更合适的事实源或问题层次；
- 指出某项选择属于产品、架构或协作决策，不能由模型代替；
- 对模型提出的协作机制给出明确修订或确认。

重复出现的直接引导可以增强置信度，但单次明确指令只对当次任务天然有效，不因此自动成为长期习惯。

以下内容不能单独作为个人习惯依据：

- 助手写出的总结、偏好标签或复盘结论；
- 从任务成功、测试通过或最终实现反推的选择；
- 注入到消息中的仓库规则、环境上下文和 Skill 正文；
- 一次性的文件、端口、版本、模型、工具参数或项目术语；
- “好”“继续”“A”之类只有结合当前选择题才有意义的回复。

记忆索引和 rollout summary 只用来定位候选会话。形成规则前必须回到原始 user turn，并至少阅读它之前模型正在采用的路径以及之后是否继续纠正或明确接受。

## 提炼方法

1. 写清转折前模型在做什么，不从单句猜意图。
2. 写清 Jamie 的输入改变了方向、焦点、方法、边界、决策权还是角色。
3. 提取改变决策的原因，而不是复制当时采用的具体技术动作。
4. 为每条候选习惯写出适用条件和一个不应泛化的反例。
5. 只有它能改善未来的自主判断，且去掉项目名后仍成立，才进入场景引用。
6. 新的直接输入与旧模式冲突时，缩小、修订或删除旧模式，不叠加更多例外。
7. 最终写成任务开始前可采用的判断标准，不写成“被纠正后如何补救”的恢复手册。

## 防止过拟合

- 某次纠正要求直接查数据库，可能是在纠正当时绕远的取证路径，不代表所有排查都数据库优先。
- 某次纠正要求先询问产品规则，不代表所有 UI 或代码细节都需要确认。
- 某次纠正要求负责人不要干涉执行者，不代表负责人不能在明确偏离、冲突或阻塞时介入。
- 某次任务要求完整交付，不代表普通“完成”自动包含推送、合并、部署或清理。

维护时优先删除弱规则和重复规则，不以覆盖更多历史为目标。
