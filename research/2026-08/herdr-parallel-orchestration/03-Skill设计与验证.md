# Skill 设计与验证

## 1. 设计定位

新 Skill 名称为 `herdr-parallel-orchestration`，放在开发区 `skills/`。它不是新的 Herdr 命令手册，也不修改正式集合中的 `installed/skills/herdr`。

职责分层：

| 层 | 权威职责 |
|---|---|
| `herdr` Skill | 环境检查、CLI 语法、ID 与状态语义、Pane/Agent 控制、安全边界 |
| `herdr-parallel-orchestration` | 主智能体持续执行、完整局部责任派发、Agent 自主判断、可见拓扑、直接交接和按需扩缩容 |
| 具体业务 Skill/项目规则 | 任务目标、实现约束、测试、授权和交付标准 |

这个分层来自 `skill-creator` 的最小指令原则：只保留会改变调度决策的非显然规则，不复制已经由 `herdr` 提供的命令细节。

## 2. 主要设计决策

| 决策 | 依据 | 没有写入的替代做法 |
|---|---|---|
| Skill 只允许手动触发，触发后多智能体默认 Herdr | 用户明确要求关闭隐式调用；原 session 又两次纠正不可见内置子代理 | 不自动介入普通任务；显式触发后，单智能体任务不为形式启动 Herdr，只有用户或必需工作流指定时使用其他机制 |
| 主智能体必须保留并持续完成具体主线工作 | 用户反复要求不要打断原工作、快速推进、停止等待和专心工作 | 不把触发 Skill 的智能体定义成纯调度者 |
| 只派发已就绪、边界清楚的局部工作 | 预占阻塞任务和交叉责任都增加了协调成本 | 不把所有可描述任务都派给 Agent |
| 全局影响动作由主智能体择机执行 | 共享环境、契约、集成和全量验证影响多个工作包 | Agent 可以提供局部事实，但不拥有全局动作 |
| 冲突优先视为任务分配错误 | 全量回归与测试修改相撞源于错误并行，而不是状态检查不足 | 不建立通用四类检查矩阵或高频扫描机制 |
| 派发完整局部责任而非预制任务队列 | 主智能体和 Herdr Agent 都有能力审查事实、规划步骤并持续推进 | 只说明结果、所有权、关键事实和权限边界，不把 Agent 降格成一次性执行器 |
| 主智能体在自己的自然检查点低频拉取状态 | 当前 Herdr CLI 没有将邻居 Agent 完成或阻塞主动注入主智能体会话的回调 | 不把“Agent 完成或阻塞”写成可自动触发的事件，也不持续 `list/read/wait` |
| 下游直接读取上游 | 用户要求减少传话，且指出等待成为瓶颈 | 不要求由主智能体重述所有细节 |
| Agent 数量跟随已就绪局部工作 | 原 session 同时出现预占、空转、扩容和缩容 | 不设置固定最小或最大 Pane 数 |
| 不打断或重置进行中的责任 | 用户要求稳定所有权；原 session 的 `/new` 是显式要求 | 不把切换机制和清空上下文作为常规调度手段 |

## 3. Skill 文件

| 文件 | 用途 |
|---|---|
| `skills/herdr-parallel-orchestration/SKILL.md` | 默认机制、主从责任边界与精简编排协议 |
| `skills/herdr-parallel-orchestration/agents/openai.yaml` | 英文原名称、简短描述、默认调用提示和调用策略 |
| `docs/skill-series.md` | 将该 Skill 登记为独立的横切协作能力 |

没有增加 `scripts/`、`references/` 或 `assets/`：当前协议长度可直接由 `SKILL.md` 承载，没有需要重复执行的确定性转换，也没有条件式大段资料。

## 5. 真实运行时验证边界

本轮只分析历史 session 并制作开发区 Skill，不接入设备 QA，也不在新的 Codex 会话中触发它。因此即使静态校验和仓库测试通过，也只能说明结构和管理逻辑成立，不能证明：

- Codex 已正确发现并能调用 `$herdr-parallel-orchestration`；
- 主智能体会在真实 Herdr 会话中持续执行，而不是退化成等待者；
- 默认 Herdr 规则会稳定阻止自行委派不可见内置子代理；
- Agent 会自主审查、规划并持续闭环责任且不越过局部边界；
- 自然检查点的低频拉取足以发现阻塞而不造成明显空转；
- 全局影响动作会由主智能体在正确时机执行；
- 局部唯一所有权能在第二个真实项目中以较少检查避免冲突。

这些项目必须通过后续显式 QA 接入和新会话行为测试取得证据。当前研究不把历史 session 的成功冒充为新 Skill 的运行时验证。
