# 软件设计：确定功能与行为

用于新增功能、调整默认行为、设计设置或自动化时。按下面的顺序确定产品行为；只处理本次涉及的部分，不要求另写一份设计报告。行为明确后，需要设计界面操作时再读取 [交互指引](interaction-preferences.md)。

## 1. 确定用户任务和功能边界

先明确用户要完成什么，以及当前哪一步造成了困难。围绕这条任务路径取舍功能，保留已经顺手的行为；不因框架通用性或竞品功能数量扩大范围。

- 核心任务应能直接完成，减少跨页面、菜单和窗口往返。
- 新功能、入口和开关应有独立用途。已有能力能表达同一意图时直接复用；已经自动完成的操作不再增加无作用的“完成”按钮。
- 权限或其他前置条件需要用户处理时，说明它与当前任务的关系；能力受限时准确呈现仍可完成的范围。

## 2. 确定设置的含义和生效方式

### 通用设置项

以下三项是已确认的跨软件默认需求。在新建应用、设计或开发设置模块时主动落实，不因当次功能描述未逐项提及而遗漏；已有实现直接复用。具体业务设置另按产品需求确定，不将应用管理功能清单混入这份通用约定。

| 设置项 | 行为约定 |
|---|---|
| 界面语言（i18n／本地化） | 提供“跟随系统”和实际支持的语言，默认跟随系统；界面文案、菜单和提示一致本地化，手动选择持久保存。优先直接生效，确需重新打开或重启时明确说明 |
| 外观模式（明暗适配） | 提供“跟随系统／浅色／深色”，默认跟随系统；窗口、控件、文字和图标随选择一致适配。跟随系统时响应系统模式变化，手动选择持久保存 |
| 版本信息 | 在设置中展示当前应用的产品版本，必要时附构建号；从应用元数据读取，保持只读，不另维护一份展示版本 |

不在通用设置中加入意见反馈、问题上报等入口。启动、更新、权限、数据和账号等项目按具体业务需求决定，不作为所有软件都需要的通用设置。

通用项可放在同一页面，复用已有版本信息区域；布局见 [通用设置项](interaction-preferences.md#通用设置项)。

当前视图的筛选、排序、显示隐藏，以及当前对象的编辑、运行、导出等主要操作，留在它们作用的界面。设置可以定义这些操作的长期默认值，不把每次执行都转移到设置。局部修复仍按本次范围进行，不自动扩成全部通用设置的补建任务。

### 明确每项设置的语义

先确定设置行为，再选择控件。每个设置应能回答下面的问题：

| 要确定的内容 | 默认约定 |
|---|---|
| 用户在选择什么 | 开关代表真实且独立的选择；已有控制能表达启停时不增加重复开关 |
| 初始值是什么 | 沿用产品已确认的默认值，取值范围服务实际使用 |
| 预设与自定义如何对应 | 两者表达同一份设置；选预设同步数值，手动修改后更新预设匹配状态 |
| 何时生效 | 能直接生效就直接生效；预览、保存与实际生效不同步时说明差异，不默认要求重启全部组件 |
| 恢复到哪里 | 明确区分系统默认、产品默认和上一次值；只承诺实际能够恢复的目标，不把内部备份机制做成含糊的恢复选项 |

设置布局、保存操作与键盘行为见 [设置页面](interaction-preferences.md#设置页面)。

## 3. 确定自动化的范围

自动化用于减少已确认任务中的维护工作，先分清它执行哪一种动作：

| 动作 | 行为约定 |
|---|---|
| 观察和记录 | 能从正常使用中取得的信息由软件维护；观察不能隐含触发重排、移动等控制动作 |
| 主动修改对象 | 按已确认的触发条件执行，尊重用户当前操作 |
| 处理新增、消失和重现 | 纳入对象的正常生命周期，不把这些变化交给用户逐项修复 |
| 自动恢复 | 明确结束条件，不无限重试或扩大控制范围 |

有明确导入、导出或纠错目的时保留手工入口。运行中的低打扰表现见 [跨屏与后台行为](interaction-preferences.md#跨屏与后台行为)。

## 4. 确定成功、失败和恢复的含义

- 成功以用户实际完成任务为准，不能仅凭权限标记或配置已保存就宣告功能可用。
- 操作成功后，相关数据、错误提示和状态显示应一致；清除旧错误不依赖另一项无关检查。
- 失败信息应给用户阅读和处理的机会，不被下一次刷新立即冲掉。反馈优先放在当前操作附近的现有区域，不另造通知中心或错误管理面板。

实现状态更新和验证真实行为时，读取 [macOS 实现与验证流程](macos-validation.md)。
