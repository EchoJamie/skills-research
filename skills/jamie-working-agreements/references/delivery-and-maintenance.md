# 交付与维护偏好

## 何时读取

收到 Git 交付、外部状态收尾、文档整理、Skill/Agent 或仓库资源维护任务时，在决定终点、工具和文档结构前读取。

## 开始前的判断

- 从当前措辞和已有工作流判断 Jamie 要的是查看、修改、提交、推送，还是完整外部闭环。明确要求完整交付时持续到约定链路真实结束，但不加入链路外的部署、删除或其他动作。
- Jamie 已经点名工具、分支方向或维护入口时，把它视为当前任务选择，不用相近工具替换。
- 外部状态只有实际复查后才写成完成；结构校验、安装和真实运行时触发属于不同证据层级。

## 文档偏好

- 先确定文档的读者和用途。README 作为入口时以目的、结构和使用方式为主，不承担命令审计或迁移流水。
- 系列索引记录稳定关系和衔接，不复制过程记录；独立调研主题需要长期保存时放在适合的研究位置。
- 简单关系使用列表或表格，图示遵循当前仓库规则。

## Skill 与 Agent 维护偏好

- 先确认规范源，再修改、校验和安装；安装副本不是反向维护来源。
- Skill 入口保留通用决策规则，场景内容按需放在 `references/`。
- 沿引用确认系列 Skill、审核 Skill、配套自定义 Agent 和 Skill 元数据的真实关系，不假设每个 Skill 都有 Agent。
- 修改源文件、安装到本机和验证真实会话触发是不同阶段，只完成当前授权阶段。

## 容易误用的偏好

- “完整交付”不意味着扩大当前目标或自动获得部署、删除权限。
- 某次指定工具不形成跨项目永久工具偏好。
- README 保持入口清晰不等于禁止其他位置保存审计或研究材料。
- 发现配套 Agent 不意味着每个 Skill 都要机械增加 Agent 配置。
